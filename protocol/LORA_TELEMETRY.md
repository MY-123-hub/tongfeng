# 智能通风系统 LoRa 应用层协议

## 1. 文档状态

本文档是控制室网关、主机和从机共同使用的 LoRa 应用层协议真源。

- 协议版本：`01`
- LoRa 模块：WH-L101-L，点对点透传模式
- LoRa 模块包长：统一配置为 `128 B`
- MCU 与 LoRa 模块串口：`115200, 8N1`
- 多字节数值：低字节在前
- 校验算法：CRC-16/MODBUS，CRC 低字节在前

旧的 `PORT:xx,NUM:xx,TM:...` ASCII 温度报文自本协议启用后废止。

WH-L101-L 模块包长支持 `32/64/128/240 B`，本项目使用 `AT+MTU=128`。模块参数依据见[WH-L101-L点对点协议说明书](https://www.usr.cn/uploads/20230524/WH-L101-L%E7%82%B9%E5%AF%B9%E7%82%B9%E5%8D%8F%E8%AE%AE%E8%AF%B4%E6%98%8E%E4%B9%A6V1.0.1-20230524162525.pdf)。

## 2. 公共报文格式

```text
[帧头][版本][类型][发送角色][发送组号][接收角色][接收组号]
[业务流水号][数据长度][数据区][CRC16]
```

| 字节位置 | 字段 | 长度 | 含义 |
| --- | --- | ---: | --- |
| 0 | 帧头1 | 1 | 固定 `AA` |
| 1 | 帧头2 | 1 | 固定 `55` |
| 2 | 版本 | 1 | 当前固定 `01` |
| 3 | 报文类型 | 1 | 见报文类型表 |
| 4 | 发送角色 | 1 | `01=控制室`、`02=主机`、`03=从机` |
| 5 | 发送组号 | 1 | 控制室固定 `00`；主机和从机为 `01~04` |
| 6 | 接收角色 | 1 | `01=控制室`、`02=主机`、`03=从机` |
| 7 | 接收组号 | 1 | 控制室固定 `00`；主机和从机为 `01~04` |
| 8 | 流水号低字节 | 1 | `flow_id` 低字节 |
| 9 | 流水号高字节 | 1 | `flow_id` 高字节 |
| 10 | 数据长度 | 1 | 后续数据区字节数，范围 `0~96` |
| 11开始 | 数据区 | 0~96 | 由报文类型决定 |
| 最后2字节 | CRC16 | 2 | CRC-16/MODBUS，低字节在前 |

总帧长计算：

```text
总帧长 = 11 + 数据长度 + 2
```

- 最短帧为 `13 B`。
- 最大帧为 `109 B`。
- `TEMP_36` 固定为 `85 B`。

CRC 计算范围：从字节2的“版本”开始，计算到数据区最后一个字节；帧头 `AA 55` 和末尾 CRC 本身不参与计算。

## 3. 角色与组号

| 设备 | 角色码 | 组号 |
| --- | --- | --- |
| 控制室网关G | `01` | `00` |
| 主机M1 | `02` | `01` |
| 主机M2 | `02` | `02` |
| 主机M3 | `02` | `03` |
| 主机M4 | `02` | `04` |
| 从机S1 | `03` | `01` |
| 从机S2 | `03` | `02` |
| 从机S3 | `03` | `03` |
| 从机S4 | `03` | `04` |

主机和从机通过拨码开关确定组号。主机只接受控制室发给本组主机的报文，以及同组从机返回的温度报文。

## 4. 报文类型表

| 类型值 | 报文名称 | 允许方向 | 作用 | 数据区长度 |
| --- | --- | --- | --- | ---: |
| `01` | `READ_TEMP` | 控制室→主机；主机→从机 | 请求一整套36点温度 | 1 |
| `02` | `TEMP_36` | 从机→主机；主机→控制室 | 一次返回36点温度 | 72 |
| `10` | `SET_FREQ` | 控制室→主机 | 设置变频器频率 | 2 |
| `11` | `SET_TARGET_TEMP` | 控制室→主机 | 设置目标温度 | 2 |
| `12` | `MANUAL_RUN` | 控制室→主机 | 切换到手动运行 | 0 |
| `13` | `MANUAL_STOP` | 控制室→主机 | 手动停止并锁定停机 | 0 |
| `14` | `SET_AUTO` | 控制室→主机 | 解除手动状态并恢复自动 | 0 |
| `15` | `QUERY_STATUS` | 控制室→主机 | 查询主机当前状态 | 0 |
| `20` | `ACK` | 主机→控制室 | 命令已接收或被拒绝 | 2 |
| `21` | `RESULT` | 主机→控制室 | 命令最终执行结果或状态 | 7 |
| `7E` | `ERROR` | 任意方向 | 协议、超时或业务处理错误 | 1~16 |

未知类型不得执行。接收端在确认帧头、版本、长度、CRC、接收角色和接收组号均正确后，才能处理数据区。

## 5. 各报文数据区

### 5.1 READ_TEMP

数据区固定1字节：

| 值 | 含义 |
| --- | --- |
| `00` | 允许主机使用未过期缓存 |
| `01` | 必须向从机请求重新采样 |

控制室向主机发送时通常使用 `00`。主机发现缓存过期后，向同组从机发送 `01`，并沿用控制室请求的业务流水号。

### 5.2 TEMP_36

数据区固定72字节，由36个 `int16_t` 温度值连续组成：

```text
[温度1低][温度1高] ... [温度36低][温度36高]
```

- 每个温度占2字节，低字节在前。
- 温度单位为 `0.1℃`。
- `250` 表示 `25.0℃`。
- `-55` 表示 `-5.5℃`。
- 数值 `0` 表示该点无效，上位机显示 `--`。
- 无效温度不参与自动启动判断，并阻止自动停机条件成立。
- 报文中不包含数据来源、快照状态和有效位图。

温度顺序固定为：

```text
温度1~6   = Port1
温度7~12  = Port2
温度13~18 = Port3
温度19~24 = Port4
温度25~30 = Port5
温度31~36 = Port6
```

### 5.3 SET_FREQ

数据区为1个 `uint16_t`，低字节在前，单位 `0.01 Hz`。

```text
5000 = 50.00 Hz = 88 13
```

### 5.4 SET_TARGET_TEMP

数据区为1个 `int16_t`，低字节在前，单位 `0.1℃`。

```text
260 = 26.0℃ = 04 01
```

### 5.5 MANUAL_RUN、MANUAL_STOP、SET_AUTO、QUERY_STATUS

数据区长度固定为0。出现额外数据时必须拒绝。

`MANUAL_STOP` 生效后，主机必须保持手动停机，直到收到并成功处理 `SET_AUTO`。

### 5.6 ACK

数据区固定2字节：

| 偏移 | 字段 | 含义 |
| ---: | --- | --- |
| 0 | 接收状态 | `00=已接受并开始处理`、`01=重复命令，未重复执行`、`02=已拒绝` |
| 1 | 原因码 | `00=无`；其他值见错误码表 |

ACK 只表示主机已经接收并判断该命令是否允许处理，不表示TD710或Flash已经执行成功。

### 5.7 RESULT

数据区固定7字节：

| 偏移 | 字段 | 长度 | 含义 |
| ---: | --- | ---: | --- |
| 0 | 结果码 | 1 | `00=成功`；其他值见错误码表 |
| 1 | 控制模式 | 1 | `00=自动`、`01=手动运行`、`02=手动停机` |
| 2 | 风机命令确认状态 | 1 | `00=已确认停止命令`、`01=已确认运行命令`、`02=未知` |
| 3 | 当前频率低字节 | 1 | 单位 `0.01 Hz` |
| 4 | 当前频率高字节 | 1 | 单位 `0.01 Hz` |
| 5 | 目标温度低字节 | 1 | 单位 `0.1℃` |
| 6 | 目标温度高字节 | 1 | 单位 `0.1℃` |

涉及TD710的命令只有在收到并验证正确的Modbus回包后才能返回成功。涉及掉电保存的命令只有在Flash保存成功后才能返回成功。

当前硬件没有接触器反馈、转速或风压反馈，因此状态 `00/01` 只表示“TD710已通过正确Modbus回包确认接受命令”，不能当成机械风机已真实转动的反馈。

### 5.8 ERROR

数据区第1字节为错误码，后续0~15字节为可选补充信息。补充信息必须是有界二进制数据，不发送无界字符串。

| 错误码 | 含义 |
| --- | --- |
| `01` | 参数或数据长度错误 |
| `02` | 当前状态不允许 |
| `03` | 主机忙或队列已满 |
| `04` | 从机响应超时 |
| `05` | TD710响应超时 |
| `06` | TD710返回异常或校验失败 |
| `07` | Flash保存失败 |
| `08` | 业务流水号冲突 |
| `09` | 不支持的报文类型或版本 |

## 6. 业务流水号

- 业务流水号为 `uint16_t`，低字节在前。
- 控制室创建新的业务流水号。
- 同一次温度请求中，控制室、主机和从机必须使用相同流水号。
- 超时重发同一业务时保持原流水号不变。
- 新业务必须使用新的流水号。
- 主机收到重复控制命令时不得重复操作TD710，应返回之前保存的ACK或RESULT。
- 流水号相同但报文类型或数据不同，视为流水号冲突。
- 主机重启后内存中的去重历史清空；控制室应在网关或主机重启后创建新流水号。

## 7. 温度读取流程

缓存新鲜：

```text
控制室 → 主机：READ_TEMP
主机   → 控制室：TEMP_36
```

缓存过期：

```text
控制室 → 主机：READ_TEMP
主机   → 从机：READ_TEMP
从机   → 主机：TEMP_36
主机   → 控制室：TEMP_36
```

从机响应超时后，主机向控制室返回 `ERROR`。主机不得把过期缓存伪装成新采样数据。

## 8. 控制命令流程

```text
控制室 → 主机：控制命令
主机   → 控制室：ACK
主机   → TD710/Flash：实际执行
主机   → 控制室：RESULT
```

`QUERY_STATUS` 不控制TD710，主机在ACK后直接返回当前状态RESULT。

## 9. 接收与错误处理规则

- CRC错误、帧长不完整、接收角色错误或接收组号错误：丢弃，不执行命令。
- 数据长度与报文类型不匹配：在进入业务层前丢弃，不回应，避免同信道的非目标设备抢答。
- 环形缓冲区溢出：丢弃受影响片段，重新寻找 `AA 55`，不得永久停止接收。
- 主机一次只允许一项TD710 Modbus事务在途。
- 温度请求超时后重发整套 `READ_TEMP`，不拆分补发单个Port或单个温度。
- 控制命令重发必须使用相同流水号，重试次数必须有限。
- 主机和从机不得主动周期广播；只对合法且与本组匹配的请求作出响应。

## 10. 当前主机时序参数

| 参数 | 当前值 | 说明 |
| --- | ---: | --- |
| 主机温度缓存新鲜期 | 5s | 超过后 `READ_TEMP=00` 仍会向从机重新采样 |
| 从机响应超时 | 3s | 超时返回 `ERROR=04` 且丢弃迟到数据 |
| TD710响应超时 | 200ms/次 | 最多2次尝试，最终超时返回 `05` |
| 自动停机回差 | 0.5℃ | 36点全部 `<= 目标-0.5℃` |
| 自动停机保持 | 60s | 数据过期、任一零值或任一点超阈值都会重新计时 |

这些值属于当前工程集中配置，现场调整时必须同步修改主机、控制室超时策略和本文档。

## 11. 控制室与上位机串口接口

控制室 STM32 的 `USART1`（PA9=TX、PA10=RX，`115200,8,N,1`）不再另设一套
文本协议：串口中的每一帧就是本文件规定的完整二进制帧。

- 上位机发送：发送者必须为控制室 `01 00`，接收者为目标主机 `02 01~04`；可发送
  `READ_TEMP`、`SET_FREQ`、`SET_TARGET_TEMP`、`MANUAL_RUN`、`MANUAL_STOP`、`SET_AUTO`、`QUERY_STATUS`。
- 控制室发送：原样转发主机返回的 `TEMP_36`、`ACK`、`RESULT`、`ERROR` 到上位机。
- 控制室每次只向 LoRa 发送一项事务。没有上位机控制命令时，按 `M1→M2→M3→M4` 自动
  请求温度；本工程当前每次启动间隔为1秒，收到对应温度/结果或超时后才开始下一项。
- 上位机的控制命令优先于下一次自动温度轮询；上位机必须保留原业务流水号直到收到同流水号
  的 `RESULT` 或 `ERROR`。

因此，上位机串口解析器可以直接复用本协议的帧头、长度和 CRC16 校验逻辑；不能再按旧版
`PORT:xx,...` 文本解析。
