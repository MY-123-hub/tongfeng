# 智能通风系统 LoRa 应用层协议

## 1. 文档状态

本文档是控制室网关、主机和从机共同使用的 LoRa 应用层协议真源。

- 协议版本：`02`
- LoRa 模块：WH-L101-L，点对点透传模式
- LoRa 模块包长：统一配置为 `128 B`
- MCU 与 LoRa 模块串口：`115200, 8N1`
- 多字节数值：低字节在前
- 校验算法：CRC-16/MODBUS，CRC 低字节在前

旧的 `PORT:xx,NUM:xx,TM:...` ASCII 温度报文自本协议启用后废止。

WH-L101-L 模块包长支持 `32/64/128/240 B`，本项目使用 `AT+MTU=128`。模块参数依据见[WH-L101-L点对点协议说明书](https://www.usr.cn/uploads/20230524/WH-L101-L%E7%82%B9%E5%AF%B9%E7%82%B9%E5%8D%8F%E8%AE%AE%E8%AF%B4%E6%98%8E%E4%B9%A6V1.0.1-20230524162525.pdf)。

### 1.1 LoRa 模块组网参数（必须统一）

本项目使用 `WMODE=TRANS` 透明传输、同一信道和应用层寻址。控制室、四台主机、四台从机的模块必须统一配置：

```text
AT+LORAPROT=NODE
AT+WMODE=TRANS
AT+CH=4700
AT+SPD=10
AT+FDMODE=OFF
AT+ADDR=88
AT+MTU=128
AT+UART=115200,8,1,NONE,NFC
AT+PMODE=RUN
```

透明传输要求所有参与双向通信的模块使用相同目标地址，因此当前现场联调统一
`AT+ADDR=88`。真正的收件人由本协议的“接收角色 + 接收组号”判定。后续恢复拨码
开关时，拨码值也只能决定应用层组号，**禁止**写入 `AT+ADDR`，否则透明传输模块
地址不一致会互相收不到数据。`65535` 是单向广播发送端地址，不用于本项目的双向
轮询链路。

## 2. 公共报文格式

```text
[帧头][版本][类型][发送角色][发送组号][接收角色][接收组号]
[业务流水号][数据长度][数据区][CRC16]
```

| 字节位置 | 字段 | 长度 | 含义 |
| --- | --- | ---: | --- |
| 0 | 帧头1 | 1 | 固定 `AA` |
| 1 | 帧头2 | 1 | 固定 `55` |
| 2 | 版本 | 1 | 当前固定 `02` |
| 3 | 报文类型 | 1 | 见报文类型表 |
| 4 | 发送角色 | 1 | `01=控制室`、`02=主机`、`03=从机`、`04=上位机（仅本地配置）` |
| 5 | 发送组号 | 1 | 控制室固定 `00`；主机和从机为 `01~04` |
| 6 | 接收角色 | 1 | `01=控制室`、`02=主机`、`03=从机` |
| 7 | 接收组号 | 1 | 控制室固定 `00`；主机和从机为 `01~04` |
| 8 | 流水号低字节 | 1 | `flow_id` 低字节 |
| 9 | 流水号高字节 | 1 | `flow_id` 高字节 |
| 10 | 数据长度 | 1 | 后续数据区字节数，范围 `0~96` |
| 11开始 | 数据区 | 0~96 | 由报文类型决定 |
| 最后2字节 | CRC16 | 2 | CRC-16/MODBUS，低字节在前 |

总帧长计算：

```text
总帧长 = 11 + 数据长度 + 2
```

- 最短帧为 `13 B`。
- 最大帧为 `109 B`。
- `TEMP_36` 固定为 `89 B`。
- `ENV_DATA` 固定为 `99 B`。

CRC 计算范围：从字节2的“版本”开始，计算到数据区最后一个字节；帧头 `AA 55` 和末尾 CRC 本身不参与计算。

## 3. 角色与组号

| 设备 | 角色码 | 组号 |
| --- | --- | --- |
| 控制室网关G | `01` | `00` |
| 主机M1 | `02` | `01` |
| 主机M2 | `02` | `02` |
| 主机M3 | `02` | `03` |
| 主机M4 | `02` | `04` |
| 从机S1 | `03` | `01` |
| 从机S2 | `03` | `02` |
| 从机S3 | `03` | `03` |
| 从机S4 | `03` | `04` |
| 上位机PC（仅控制室有线口配置） | `04` | `00` |

M1/S1～M4/S4使用同一套固件。主机和从机上电读取一次拨码并冻结组号，运行期间
不得因拨码抖动改变身份。主机只接受控制室发给本组主机的报文，以及同组从机返回
的温度或环境报文。控制室默认轮询四组，也可由上位机本地配置活动组列表。

## 4. 报文类型表

| 类型值 | 报文名称 | 允许方向 | 作用 | 数据区长度 |
| --- | --- | --- | --- | ---: |
| `01` | `READ_TEMP` | 控制室→主机；主机→从机 | 请求一整套36点温度 | 1 |
| `02` | `TEMP_36` | 从机→主机；主机→控制室 | 返回36点温度及主从机BME温度 | 76 |
| `03` | `READ_ENV` | 控制室→主机；主机→从机 | 请求湿度、绝对气压和雨滴预留值 | 1 |
| `04` | `ENV_DATA` | 从机→主机；主机→控制室 | 返回36点湿度、主从机BME环境值及雨滴预留值 | 86 |
| `10` | `SET_FREQ` | 控制室→主机 | 设置变频器频率 | 2 |
| `11` | `SET_TARGET_TEMP` | 控制室→主机 | 设置目标温度 | 2 |
| `12` | `MANUAL_RUN` | 控制室→主机 | 切换到手动运行 | 0 |
| `13` | `MANUAL_STOP` | 控制室→主机 | 手动停止并锁定停机 | 0 |
| `14` | `SET_AUTO` | 控制室→主机 | 解除手动状态并恢复自动 | 0 |
| `15` | `QUERY_STATUS` | 控制室→主机 | 查询主机当前状态 | 0 |
| `16` | `TIME_SYNC` | 控制室→主机 | 校正主机计划时钟 | 6 |
| `20` | `ACK` | 主机→控制室 | 命令已接收或被拒绝 | 2 |
| `21` | `RESULT` | 主机→控制室 | 命令最终执行结果或状态 | 7 |
| `30` | `HOST_LIST` | 上位机→控制室（仅有线本地） | 配置1～4个活动主机组号 | 1～4 |
| `7E` | `ERROR` | 任意方向 | 协议、超时或业务处理错误 | 1~16 |

未知类型不得执行。接收端在确认帧头、版本、长度、CRC、接收角色和接收组号均正确后，才能处理数据区。

## 5. 各报文数据区

### 5.1 READ_TEMP

数据区固定1字节：

| 值 | 含义 |
| --- | --- |
| `00` | 允许主机使用未过期缓存 |
| `01` | 必须向从机请求重新采样 |

控制室向主机发送时通常使用 `00`。主机发现缓存过期后，向同组从机发送 `01`，并沿用控制室请求的业务流水号。

### 5.2 TEMP_36

数据区固定76字节，由36个节点温度和两套BME280温度组成：

```text
[温度1低][温度1高] ... [温度36低][温度36高]
[从机BME温度低][从机BME温度高][主机BME温度低][主机BME温度高]
```

- 每个温度占2字节，低字节在前。
- 温度单位为 `0.1℃`。
- `250` 表示 `25.0℃`。
- `-55` 表示 `-5.5℃`。
- `0x8000` 表示温度无效，上位机显示 `--`；数值 `0` 是有效的 `0.0℃`。
- 无效温度不参与自动启动判断，并阻止自动停机条件成立。
- 报文中不包含数据来源、快照状态和有效位图。

温度顺序固定为：

```text
温度1~6   = Port1
温度7~12  = Port2
温度13~18 = Port3
温度19~24 = Port4
温度25~30 = Port5
温度31~36 = Port6
```

### 5.3 READ_ENV

数据区固定1字节，`00`允许使用缓存，`01`要求重新采样。温度请求与环境请求是两个
独立事务，使用不同流水号，任一事务完成后都不等待另一类响应。

### 5.4 ENV_DATA

数据区固定86字节，小端序：

| 数据区偏移 | 长度 | 字段 | 编码 |
| ---: | ---: | --- | --- |
| 0～71 | 72 | 36路GXHT3W湿度 | `uint16_t`，0.1%RH，`FFFF`无效 |
| 72～73 | 2 | 从机BME湿度 | `uint16_t`，0.1%RH，`FFFF`无效 |
| 74～75 | 2 | 主机BME湿度 | `uint16_t`，0.1%RH，`FFFF`无效 |
| 76～79 | 4 | 从机BME绝对气压 | `uint32_t`，Pa，`FFFFFFFF`无效 |
| 80～83 | 4 | 主机BME绝对气压 | `uint32_t`，Pa，`FFFFFFFF`无效 |
| 84～85 | 2 | 从机PB1雨滴预留值 | 当前固定 `FFFF` |

从机响应中主机BME字段填写无效值，主机转发前写入本机BME数据。雨滴字段由从机
产生并由主机原样转发；正式测试前不配置PB1，也不得解释 `0000～FFFE` 的物理含义。

### 5.5 SET_FREQ

数据区为1个 `uint16_t`，低字节在前，单位 `0.01 Hz`。

```text
5000 = 50.00 Hz = 88 13
```

### 5.6 SET_TARGET_TEMP

数据区为1个 `int16_t`，低字节在前，单位 `0.1℃`。

```text
260 = 26.0℃ = 04 01
```

### 5.7 MANUAL_RUN、MANUAL_STOP、SET_AUTO、QUERY_STATUS

数据区长度固定为0。出现额外数据时必须拒绝。

`MANUAL_STOP` 生效后，主机必须保持手动停机，直到收到并成功处理新的 `MANUAL_RUN`
或 `SET_AUTO`。

### 5.8 TIME_SYNC

数据区固定6字节：`year:uint16 little-endian, month:uint8, day:uint8, hour:uint8, minute:uint8`。
主机只接受合法公历时间；收到后立即校正本地软件时钟，随后以本地时钟继续推进。
该报文不要求 `ACK` 或 `RESULT`。

主机每次上电都必须进入手动停机状态并主动向TD710发送停止命令。Flash只保留频率、
目标温度等设定值，不允许根据掉电前的运行模式自动恢复风机运行；上电后必须收到新的
`MANUAL_RUN` 或 `SET_AUTO` 才能离开手动停机状态。

### 5.9 ACK

数据区固定2字节：

| 偏移 | 字段 | 含义 |
| ---: | --- | --- |
| 0 | 接收状态 | `00=已接受并开始处理`、`01=重复命令，未重复执行`、`02=已拒绝` |
| 1 | 原因码 | `00=无`；其他值见错误码表 |

ACK 只表示主机已经接收并判断该命令是否允许处理，不表示TD710或Flash已经执行成功。
`ACK=02（已拒绝）` 是该事务的终止响应，控制室和上位机收到后必须立即释放该流水号，
不得继续等待 `RESULT/ERROR`，也不得在6秒后把它改报为主机超时。`ACK=00/01` 仍需等待
同流水号的 `RESULT` 或 `ERROR`。

### 5.10 RESULT

数据区固定7字节：

| 偏移 | 字段 | 长度 | 含义 |
| ---: | --- | ---: | --- |
| 0 | 结果码 | 1 | `00=成功`；其他值见错误码表 |
| 1 | 控制模式 | 1 | `00=自动`、`01=手动运行`、`02=手动停机` |
| 2 | 风机命令确认状态 | 1 | `00=已确认停止命令`、`01=已确认运行命令`、`02=未知` |
| 3 | 当前频率低字节 | 1 | 单位 `0.01 Hz` |
| 4 | 当前频率高字节 | 1 | 单位 `0.01 Hz` |
| 5 | 目标温度低字节 | 1 | 单位 `0.1℃` |
| 6 | 目标温度高字节 | 1 | 单位 `0.1℃` |

涉及TD710的命令只有在收到并验证正确的Modbus回包后才能返回成功。运行模式不做掉电
恢复，因此 `MANUAL_RUN/MANUAL_STOP/SET_AUTO` 不擦写Flash。`SET_FREQ` 在Modbus回包
正确后立即更新运行参数并返回结果，频率在最后一次成功修改3秒后合并写入Flash；写入
失败后每5秒后台重试，并用原流水号补发 `ERROR=07` 提醒上位机“指令已执行但掉电保存
失败”。`SET_TARGET_TEMP` 仍需Flash保存成功后才返回成功。

当前硬件没有接触器反馈、转速或风压反馈，因此状态 `00/01` 只表示“TD710已通过正确Modbus回包确认接受命令”，不能当成机械风机已真实转动的反馈。

### 5.11 ERROR

数据区第1字节为错误码，后续0~15字节为可选补充信息。补充信息必须是有界二进制数据，不发送无界字符串。

| 错误码 | 含义 |
| --- | --- |
| `01` | 参数或数据长度错误 |
| `02` | 当前状态不允许 |
| `03` | 主机忙或队列已满 |
| `04` | 从机响应超时 |
| `05` | TD710响应超时 |
| `06` | TD710返回异常或校验失败 |
| `07` | Flash保存失败 |
| `08` | 业务流水号冲突 |
| `09` | 不支持的报文类型或版本 |
| `0A` | 控制室等待目标主机响应超时（仅控制室发往上位机） |

控制室本地产生的错误沿用以上错误码：目标组不在 `01～04` 时返回 `02`，上位机命令
队列已满时返回 `03`。本地错误帧不进入LoRa空口；其发送者为控制室 `01 00`，接收者
保留原命令的目标主机和组号，以便上位机按流水号结束对应命令。

## 6. 业务流水号

- 业务流水号为 `uint16_t`，低字节在前。
- 控制室创建新的业务流水号。
- 同一次温度或环境请求中，控制室、主机和从机必须使用相同流水号。
- 温度与环境是独立事务，必须使用不同流水号。
- 超时重发同一业务时保持原流水号不变。
- 新业务必须使用新的流水号。
- 主机收到重复控制命令时不得重复操作TD710，应返回之前保存的ACK或RESULT。
- 流水号相同但报文类型或数据不同，视为流水号冲突。
- 主机重启后内存中的去重历史清空；控制室应在网关或主机重启后创建新流水号。

## 7. 遥测读取流程

缓存新鲜：

```text
控制室 → 主机：READ_TEMP
主机   → 控制室：TEMP_36
```

缓存过期：

```text
控制室 → 主机：READ_TEMP
主机   → 从机：READ_TEMP
从机   → 主机：TEMP_36
主机   → 控制室：TEMP_36
```

从机响应超时后，主机向控制室返回 `ERROR`。主机不得把过期缓存伪装成新采样数据。
环境事务使用相同流程，将 `READ_TEMP/TEMP_36` 替换为 `READ_ENV/ENV_DATA`，且不等待
另一类帧共同完成。

## 8. 控制命令流程

```text
控制室 → 主机：控制命令
主机   → 控制室：ACK
主机   → TD710/Flash：实际执行
主机   → 控制室：RESULT
```

`QUERY_STATUS` 不控制TD710，主机在ACK后直接返回当前状态RESULT。

## 9. 接收与错误处理规则

- CRC错误、帧长不完整、接收角色错误或接收组号错误：丢弃，不执行命令。
- 数据长度与报文类型不匹配：在进入业务层前丢弃，不回应，避免同信道的非目标设备抢答。
- 环形缓冲区溢出：丢弃受影响片段，重新寻找 `AA 55`，不得永久停止接收。
- 主机一次只允许一项TD710 Modbus事务在途。
- 遥测请求超时后重发当前类型的完整请求，不拆分补发单个Port或单个传感器。
- 控制命令重发必须使用相同流水号，重试次数必须有限。
- 主机和从机不得主动周期广播；只对合法且与本组匹配的请求作出响应。

## 10. 当前主机时序参数

| 参数 | 当前值 | 说明 |
| --- | ---: | --- |
| 主机温度缓存新鲜期 | 5s | 超过后 `READ_TEMP=00` 仍会向从机重新采样 |
| 主机环境缓存新鲜期 | 5s | 超过后重新读取同组从机环境缓存 |
| 主机本机BME缓存新鲜期 | 2s | 超过后主机BME字段填写无效值 |
| 从机响应超时 | 3s | 超时返回 `ERROR=04` 且丢弃迟到数据 |
| LoRa 收发保护间隔 | 50ms | 节点完整接收一帧后，至少等待50ms再从同一模块发送下一帧 |
| TD710响应超时 | 200ms/次 | 最多2次尝试，最终超时返回 `05` |
| 自动停机回差 | 0.5℃ | 36点全部 `<= 目标-0.5℃` |
| 自动停机保持 | 60s | 数据过期、任一 `0x8000` 无效值或任一点超阈值都会重新计时 |

这些值属于当前工程集中配置，现场调整时必须同步修改主机、控制室超时策略和本文档。

## 11. 控制室与上位机串口接口

控制室 STM32 的 `USART1`（PA9=TX、PA10=RX，`115200,8,N,1`）不再另设一套
文本协议：串口中的每一帧就是本文件规定的完整二进制帧。

- 上位机发送遥测或控制命令时，发送者为控制室 `01 00`，接收者为 `M1～M4`；还可用
  `04 00 → 01 00` 的本地 `HOST_LIST(0x30)` 配置活动组列表。
- 控制室原样转发主机返回的 `TEMP_36`、`ENV_DATA`、`ACK`、`RESULT`、`ERROR`。
- 控制室每次只向LoRa发送一项事务，默认顺序为
  `M1温度→M1环境→M2温度→M2环境→M3温度→M3环境→M4温度→M4环境`。
- 当前事务收到匹配响应或超时后才进入下一项；单组超时不得阻塞其他组。
- 上位机的控制命令优先于下一次自动温度轮询；上位机必须保留原业务流水号直到收到同流水号
  的 `RESULT`、`ERROR` 或 `ACK=02`。上位机自身等待8秒仍无终止响应时，必须释放按钮并
  显示本地超时，不能无限等待控制室兜底。

因此，上位机串口解析器可以直接复用本协议的帧头、长度和 CRC16 校验逻辑；不能再按旧版
`PORT:xx,...` 文本解析。
