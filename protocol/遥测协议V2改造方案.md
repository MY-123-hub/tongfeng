# 通风系统遥测协议 V2 改造方案

> 历史方案说明：本文档中的“同一流水号联合双帧”方案已停止采用。当前设计以
> [`LORA_TELEMETRY_V2_DESIGN.md`](./LORA_TELEMETRY_V2_DESIGN.md) 为唯一实施依据；
> 新方案将温度与湿度/气压定义为两类完全独立的请求和响应。

## 1. 方案结论

采用同一 `flow_id` 关联的两帧结构，保留现有 `96 B` 最大数据区、`109 B` 最大应用帧和 LoRa `MTU=128`，无需扩大缓冲区：

- `0x02 TEMPERATURE_DATA`：36 路探头温度及主、从机 BME280 温度，数据区 `76 B`，整帧 `89 B`。
- `0x03 HUMIDITY_PRESSURE_DATA`：36 路探头湿度及主、从机 BME280 湿度、绝对气压，数据区 `84 B`，整帧 `97 B`。
- `0x01` 请求的语义由 `READ_TEMP` 扩展为 `READ_TELEMETRY`，仍保留“允许缓存/强制重采样”参数。
- 协议版本统一升级为 `0x02`，主机、从机、控制室、上位机同步升级，不兼容旧版 `85 B` 温度帧。

GXHT3W 沿用已经过实物验证的 `LoraSlave.switch match` 解码方式，本次不调整其家族码、原始位宽或字节序。参考资料：

- `温湿度传感器单总线协议.pdf`
- `GXHT3WM规格书.pdf`

## 2. 当前方案的优缺点

### 2.1 优点

- 两帧都低于现有协议和 LoRa 长度限制，不需要修改模块 MTU。
- 可以保留 `0.1 ℃`、`0.1 %RH` 和 `1 Pa` 的数据精度。
- 主机、从机 BME280 字段位置固定，从机先填占位值，主机转发前覆盖自己的数据，四端容易保持一致。
- 两帧使用同一流水号并整套提交，避免数据库中的温度、湿度和气压来自不同采样事务。
- 温度帧与原 `TEMP_36` 结构接近，对现有自动控制逻辑影响较小。

### 2.2 缺点

- 一次采样需要发送两个无线包，空口占用时间和丢包概率增加。
- 主机、控制室和上位机都需要增加双帧缓存、完整性位图和超时处理。
- 任意一帧丢失都会使整套数据作废，需要重新采样，不能只补发缺失帧。
- V2 协议要求四端同步升级；旧固件会拒绝新版本帧。
- 主机与从机的 BME280 位于不同位置，采样时刻只能尽量接近，无法做到严格同步。

## 3. 通用帧结构

通用帧头结构保持不变，仅将协议版本改为 `0x02`：

| 帧字节位置 | 长度 | 字段 | 说明 |
|---:|---:|---|---|
| 0–1 | 2 B | 帧头 | 固定 `AA 55` |
| 2 | 1 B | 协议版本 | V2 固定为 `02` |
| 3 | 1 B | 消息类型 | `01`、`02`、`03` 等 |
| 4 | 1 B | 发送角色 | 控制室、主机或从机 |
| 5 | 1 B | 发送组号 | 主从机组号为 `1–4` |
| 6 | 1 B | 接收角色 | 控制室、主机或从机 |
| 7 | 1 B | 接收组号 | 控制室为 `0`，主从机为 `1–4` |
| 8–9 | 2 B | `flow_id` | 小端序，同一采样的两帧必须相同 |
| 10 | 1 B | 数据区长度 | 温度帧 `76`，湿度/气压帧 `84` |
| 11–N | 可变 | 数据区 | 按下文固定位置解释 |
| N+1–N+2 | 2 B | CRC16 | CRC-16/MODBUS，低字节在前 |

CRC 计算范围仍为从版本字节到数据区最后一个字节，不包含 `AA 55` 帧头和末尾 CRC。

所有多字节数据均采用小端序。

## 4. 统一数据位置

36 路传感器顺序固定如下：

```text
索引 0～5   = Port1 的传感器 1～6
索引 6～11  = Port2 的传感器 1～6
索引 12～17 = Port3 的传感器 1～6
索引 18～23 = Port4 的传感器 1～6
索引 24～29 = Port5 的传感器 1～6
索引 30～35 = Port6 的传感器 1～6
```

### 4.1 温度帧 `0x02 TEMPERATURE_DATA`

数据区长度固定为 `76 B`，整帧长度固定为 `89 B`。

| 数据区偏移 | 长度 | 数据类型 | 内容 | 单位/无效值 |
|---:|---:|---|---|---|
| 0–71 | 72 B | `int16_t[36]` | 36 路探头温度 | `0.1 ℃`；无效为 `0x8000` |
| 72–73 | 2 B | `int16_t` | 从机 BME280 温度 | `0.1 ℃`；无效为 `0x8000` |
| 74–75 | 2 B | `int16_t` | 主机 BME280 温度 | `0.1 ℃`；无效为 `0x8000` |

从机向主机发送时，偏移 `74–75` 必须填写 `0x8000`。主机转发给控制室之前，使用自身 BME280 的有效数据覆盖该位置；数据无效或过期时继续保留 `0x8000`。

### 4.2 湿度/气压帧 `0x03 HUMIDITY_PRESSURE_DATA`

数据区长度固定为 `84 B`，整帧长度固定为 `97 B`。

| 数据区偏移 | 长度 | 数据类型 | 内容 | 单位/无效值 |
|---:|---:|---|---|---|
| 0–71 | 72 B | `uint16_t[36]` | 36 路探头湿度 | `0.1 %RH`；无效为 `0xFFFF` |
| 72–73 | 2 B | `uint16_t` | 从机 BME280 湿度 | `0.1 %RH`；无效为 `0xFFFF` |
| 74–75 | 2 B | `uint16_t` | 主机 BME280 湿度 | `0.1 %RH`；无效为 `0xFFFF` |
| 76–79 | 4 B | `uint32_t` | 从机 BME280 绝对气压 | `Pa`；无效为 `0xFFFFFFFF` |
| 80–83 | 4 B | `uint32_t` | 主机 BME280 绝对气压 | `Pa`；无效为 `0xFFFFFFFF` |

从机向主机发送时，偏移 `74–75` 必须填写 `0xFFFF`，偏移 `80–83` 必须填写 `0xFFFFFFFF`。主机转发前使用自身 BME280 数据覆盖这些位置。

### 4.3 无效数据规则

- 温度无效值统一为 `0x8000`。
- 湿度无效值统一为 `0xFFFF`。
- 绝对气压无效值统一为 `0xFFFFFFFF`。
- DS18B20 只能提供温度，对应湿度位置必须填写 `0xFFFF`。
- GXHT3W 或 BME280 未连接、CRC错误、读取失败或数值超出有效范围时，填写相应无效值。
- 真实 `0.0 ℃`、`0.0 %RH` 必须作为有效数据保留，不能再用数值 `0` 表示无效。
- 单个传感器字段无效不导致整套事务失败；帧缺失、CRC错误、长度错误或流水号不一致才导致整套事务作废。

## 5. 双帧事务规则

### 5.1 请求流程

```text
控制室 → 主机：READ_TELEMETRY，flow_id = X
主机   → 从机：READ_TELEMETRY，flow_id = X
从机   → 主机：TEMPERATURE_DATA，flow_id = X
从机   → 主机：HUMIDITY_PRESSURE_DATA，flow_id = X
主机   → 控制室：TEMPERATURE_DATA，flow_id = X
主机   → 控制室：HUMIDITY_PRESSURE_DATA，flow_id = X
控制室 → 上位机：完整的两帧，flow_id = X
```

### 5.2 完整性要求

- 两帧必须使用相同的发送方、组号和 `flow_id`。
- 接收方用两位完整性位图记录温度帧和湿度/气压帧。
- 允许两帧以任意顺序到达，但发送端固定先发温度帧。
- 从机两帧的发送间隔不得小于 `20 ms`，避免 `UARTFT=10ms` 将两个应用帧合并为一个超过 MTU 的 LoRa 包。
- 主机只有在收到完整帧对后才更新缓存和准备上行数据。
- 控制室只有在收到完整帧对后才向上位机转发，禁止转发半套数据。
- 上位机只有在收到完整帧对后才刷新界面和写入数据库。
- 任意一帧缺失、损坏或流水号不匹配，整套临时数据全部丢弃并重新采样。
- 单个传感器使用无效哨兵不属于双帧失败，完整数据仍可显示和保存。

## 6. 四端代码改造

### 6.1 从机

- 将当前只返回温度的采样结果扩展为完整遥测快照：36 路温度、36 路湿度和从机 BME280 温湿压。
- GXHT3W 一次读取同时保存温度和湿度，沿用已经实测正确的参考工程解码方式。
- DS18B20 正常保存温度，对应湿度写 `0xFFFF`。
- 修改温度转换逻辑，允许真实 `0.0 ℃`；读取函数返回失败时才写无效值。
- 每次遥测请求只读取一次从机 BME280，并校验：
  - 温度范围 `-40.0～85.0 ℃`；
  - 湿度范围 `0.0～100.0 %RH`；
  - 绝对气压范围 `30000～110000 Pa`。
- BME280 任一读取过程失败时，其三个字段均写无效值。
- 构造两帧时，主机 BME280 字段固定填无效值。
- 扩展发送状态机，先发温度帧，等待至少 `20 ms` 后发送湿度/气压帧。
- 同一 `flow_id` 的重复请求应重新发送完整两帧；每帧独立执行有限重试并记录诊断计数。

### 6.2 主机 `_TD710`

- 将现有温度缓存扩展为完整双帧遥测缓存，并记录两帧完整性位图。
- 接收从机数据时校验版本、方向、组号、类型、长度、CRC和 `flow_id`。
- 两帧允许乱序到达，但只有两帧都有效时才提交为新的缓存。
- 收齐两帧后，把主机 BME280 数据写入预留位置，再向控制室发送完整帧对。
- 主机 BME280 使用采样时间不超过 `2 s` 的最新有效缓存，不阻塞 LoRa 事务。
- 主机 BME280 数据过期或采样失败时，三个字段写对应无效值。
- 缓存回复必须返回原来同一套完整帧对，不把新主机数据混入旧从机数据。
- 自动通风控制仍只使用36路探头温度，不因新增字段改变启停判断。
- 保留当前主机 BME280、FreeRTOS队列和工程配置中的未提交改动，在其基础上增量修改，不覆盖或回退。

### 6.3 控制室

- 协议版本改为 V2，增加 `0x03` 类型和两个固定数据区长度校验。
- 为当前事务缓存主机返回的两帧和完整性位图。
- 收到第一帧时只保存，不立即向上位机发送，也不结束轮询事务。
- 收齐同一 `flow_id` 的两帧后，按温度帧、湿度/气压帧顺序转发给上位机，再结束事务。
- 缺帧、错帧或超时后清除整个临时帧对；手动请求返回错误，自动轮询静默进入下一轮。
- 控制室继续作为二进制网关，不承担 BME280 数据计算或单位转换。

### 6.4 上位机

- 协议解析支持 V2、`0x02` 温度帧和 `0x03` 湿度/气压帧。
- 按 `(sender_group, flow_id)` 缓存两帧，只有完整数据集才提交。
- 36 个传感器格继续分别显示温度和湿度。
- 新增“从机 BME280”和“主机 BME280”两个独立区域，各显示温度、湿度和绝对气压。
- 界面统一使用“绝对气压（kPa）”，不再把 BME280 数据称为真实风压。
- 无效哨兵转换为 `None`，界面显示 `--`，数据库写入 `NULL`。
- 请求按钮和自动轮询只有在收到完整帧对、明确错误或超时后才能释放。
- CSV 导出增加六个 BME280 字段及明确单位。

## 7. 上位机数据库变更

保留现有表和旧字段，不删除、不重命名历史列。通过 `PRAGMA table_info(sensor_data)` 检查字段，并仅对缺少的字段执行 `ALTER TABLE ADD COLUMN`。

新增字段：

| 字段名 | 类型 | 含义 |
|---|---|---|
| `slave_bme_temperature_c` | `REAL` | 从机 BME280 温度，℃ |
| `slave_bme_humidity_rh` | `REAL` | 从机 BME280 湿度，%RH |
| `slave_bme_pressure_pa` | `INTEGER` | 从机 BME280 绝对气压，Pa |
| `master_bme_temperature_c` | `REAL` | 主机 BME280 温度，℃ |
| `master_bme_humidity_rh` | `REAL` | 主机 BME280 湿度，%RH |
| `master_bme_pressure_pa` | `INTEGER` | 主机 BME280 绝对气压，Pa |

迁移必须是幂等的，多次启动不能重复增加字段；已有记录保留，新字段默认为 `NULL`。

## 8. 结构优化方向

- 在 `protocol/` 中维护固件共用的协议常量头文件，集中定义版本、消息类型、字段偏移、长度、单位和无效值。
- 三个 STM32 工程引用同一份协议常量，避免主机、从机和控制室分别维护魔数。
- Python 端保留对应常量，并通过跨语言黄金帧测试验证与 C 固件一致。
- 将“采样快照”“双帧收集状态”和“已提交缓存”分成三个数据对象，防止半套数据覆盖有效缓存。
- 发送和接收状态机使用显式枚举和超时，不在中断中采样、组帧或执行阻塞发送。
- 增加以下诊断计数：温度帧接收、湿度帧接收、帧对完成、帧对超时、流水号不一致、BME过期、字段无效和发送重试。

## 9. 测试与验收

### 9.1 协议测试

- 验证两个响应类型的数据区长度分别为 `76 B` 和 `84 B`。
- 验证整帧长度分别为 `89 B` 和 `97 B`。
- 验证每个字段的固定偏移、大小端、单位和无效值。
- 生成 V2 CRC 黄金向量，并在从机、主机、控制室和 Python 中得到相同结果。
- 验证最大帧仍不超过 `109 B`，无需修改 `MTU=128`。

### 9.2 从机测试

- GXHT3W 温度和湿度同时进入同一索引。
- DS18B20 温度有效且湿度为 `0xFFFF`。
- 空端口、读取失败和 CRC 错误使用无效值。
- 真实 `0.0 ℃` 不再被判定为无效。
- BME280 成功、初始化失败、读取失败和越界数据处理正确。
- 主机 BME280 预留字段为规定的无效值。
- 两帧间隔、有限重试和重复请求重发完整帧对正确。

### 9.3 主机测试

- 正序和逆序收到两帧都能组成完整快照。
- 只收到一帧、不同流水号、重复帧、错误长度和错误CRC不会提交缓存。
- 主机 BME280 在 `2 s` 内有效时写入两帧，过期或失败时写无效值。
- 缓存请求返回同一套完整数据，不混合不同时间的字段。
- 新协议不改变现有自动控制、变频器命令和参数存储逻辑。

### 9.4 控制室测试

- 第一帧到达后不向上位机转发。
- 完整帧对到达后按固定顺序转发两帧。
- 缺帧、错序、不同流水号和超时能清除临时缓存。
- 自动轮询在帧对完成前不会启动下一事务。

### 9.5 上位机测试

- 正确解析和关联两帧，半套数据不刷新界面、不写数据库。
- 36 路温湿度以及主、从 BME280 六项数据显示正确。
- 所有无效哨兵正确转换为 `None/NULL/--`。
- 已有数据库可以无损增加六列，重复启动迁移保持幂等。
- 历史读取和 CSV 导出字段、单位正确。

### 9.6 端到端与构建

执行完整链路测试：

```text
控制室请求
→ 主机转发
→ 从机采样并发送双帧
→ 主机补齐本机 BME280
→ 控制室收齐并成对转发
→ 上位机一次显示和入库
```

完成代码修改后应执行：

- Windows 主机协议和状态机测试：`tests/host/run_tests.ps1`。
- 上位机 Python 测试：`上位机/tests/test_protocol.py`。
- 主机、从机、控制室三个 Keil 工程全量构建。
- 实机对照温湿度计和气压参考值进行联调。

## 10. 已确认的实施前提

- GXHT3W 参考工程的温湿度已经通过真实硬件验证，因此本次不修改其底层换算。
- BME280 的压力字段定义为绝对气压，不代表风道差压。
- 两帧缺一即整套作废；单个传感器字段无效不影响其他有效数据。
- 主机使用 `2 s` 内的最新 BME280 数据，过期时填写无效值。
- 主、从机 BME280 在上位机中分开展示。
- 已授权上位机 SQLite 非破坏性新增六列并保留旧数据。
- 当前仓库存在未提交的主机 BME280 和工程配置修改，实施时必须保留并增量合并。
- 当前命令行环境缺少 GCC、Keil 命令行入口和 PyInstaller。完整固件构建、实机联调及新版 EXE 打包需要对应工具环境；本次代码改造默认不更新现有预编译 EXE。
